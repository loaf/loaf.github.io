点点点，点点点：当 AI 在省略号里偷偷算数学

loaf 2026-07-21 大约 7 分钟 随笔 人工智能 LLM AI

这也太荒谬了吧？

在X上看到一篇推文：

内容是：

你问一个前沿大模型问一个问题：“谁在（1900 + 莫扎特去世时的年龄）年获得了诺贝尔化学奖？”

它答错了。

然后你把同样的问题原封不动再问一遍，只是这次你在问题后附加上和300个点。

它答对了。

我想你的第一反应和我一样：你在开什么玩笑？

问题是，这不是一个玩笑。这居然是一篇严肃的论文《Reading Between the Dots: Decoding Hidden Computation across Filler Tokens》1。

空间太小，写不下证明过程?

要理解这件事，得先接受 Transformer 一个很基础的限制。

你知道所谓的"思考"，在 LLM 里到底是什么吗？是矩阵乘法的堆叠。每一次生成一个 token，模型对那个位置只能跑固定层数的前向传播——比如 DeepSeek V3 是 60 层。

也就是说，每一个 token 位置，模型拥有的"计算预算"是封顶的。

想象一个学生做数学题。

你让他心算 74 + 6 + 13 + 22，他要在脑子里一步步算，容易错。你给他一张草稿纸，让他把中间结果写下来，他就不容易错了。

Transformer 也是这样。

当你问"钨原子序数 + 碳原子序数 = ？“又不给它思考空间，它必须在答案那一个 token 位置上完成全部四步：检索钨=74 → 检索碳=6 → 算 74+6=80 → 输出。

这四步要挤在那一个位置的 60 层里跑完。深度不够用，容易算错。

论文用 logit lens 直接证明了这一点：所有中间值都堆在答案位置那一个点上，按层深度依次浮现。这是"被压到极致"的计算。

那串省略号到底做了什么？

回到哪些看似没有用的点点，每个点其实都是会被理解成一个token，而这些token位置都会经过完整的 60 层处理。模型把原本挤在一个位置的多步计算，摊薄到多个位置上。

点换成 1 2 3 4 5 也行，换成 a b c d e 也行。只要是模型熟悉的、不捣乱的 token 序列，都管用。

但你用随机字符，乱码什么的填充的话就明显变差了。为什么？

干净的草稿纸能写字；但如果纸上印满了乱七八糟的图案，反而干扰你写字。所以这些占位的token 必须是干净的、重复的、低信息量的，模型才能把它当成纯粹的工作内存。

Transformer的计算维度

等等，Transformer 不是算每个 token 之间的关系吗？token 越多，注意力关系越复杂，越吃算力。为什么反而会增加工作内存？

这是因为，Transformer 有两个完全独立的计算维度。

上面说的，其实只是Transformer计算的维度之一：宽度方向上的Token之间的关系。

每个 token 要"看"其他所有 token，建立关系。这个维度的复杂度是 O(n²)——序列越长，关系越复杂，越吃算力。这是横向的，是 token 之间的。

另外它还有一个深度方向上的关系，是对每个Token自己的层层处理。

每个 token 位置都要经过模型的所有层的前向传播。DeepSeek V3 是 60 层，意味着每个 token 位置都享受完整的 60 层处理。这是纵向的，是单个 token 内部的。

上面的那些点点点，增加的就是深度方向的可用位置。

每个点有60层运算，加上300个点，相当于多了300个60层的小网络，通过注意力做分布式计算了。

这可有点反直觉，这难道不会指数级地增加运算量吗？

事实上，这个直觉是正确的，论文里也提到了这一点，并且附加上几个条件：

一是这个填充用的Toekn（下面会统一用论文中说的 filler token 来代替）必须是高度同质化的或关系非常简单的，比如都是“…..”、“12345”之类，这样它们之间的注意力关系极其简单。模型不需要为它们建立复杂的关系图。所以在宽度方向上的负担增长很慢，但深度红利却很可观。

二是长度也是有一定限制的，不能无限增长。论文里有一个数据 k>500 之后，准确率开始饱和甚至退化。

三个证据，证明这不是巧合

论文给了三条互相印证的证据来证明模型真的在filler token里做了计算，而不只是一种巧合。这三条证据分别是：

1.Attention路由

Attention 路由，证明了模型在算题时，注意力真的会绕进 filler 区再回到答案，而不是跳过 filler 直接问答。

简单说就是，你让两人传话。正常情况小明直接把话传给小红（问题→答案，跳过中间）。但你发现，当中间站着个"哑巴”（filler 区，不会说话），小明居然先把话传给哑巴，再从哑巴传给小红——小红最后还答对了。说明哑巴虽然在"装死"，但小明其实把信息递给它了，它内部有动作。

2.Logit-lens读取

Logit-lens 读取，证明了 filler 区的内部向量真的编码了中间值（比如 76、93、128 这些数字），不是空的。用Logit-lens把向量翻译回来能看到这些内容。

回到上面的例子，就是你发现了了哑巴怀里抱着一张纸条，上面写着"76+93"，而算出来的值正是小明需要传给小红的。

3.KV-cache 移植

KV-cache 移植，证明了把 filler 区的内部状态换掉，答案也跟着变——这是因果证据，证明 filler 真的"导致"了答案，不只是凑巧相关。

还是那个例子，你发现了哑巴怀中的那张草稿，发现上面写着76+93，现在你将这个草稿替换掉，小红的答案就变化了。

三条证据合起来，几乎堵死了所有"这只是噪声"的解释。

好吧，我知道AI可以在省略号里计算，那又怎么样？

这些研究者写论文可不是为了水职称。

他们是在挑战一个AI安全思路，叫 CoT 监控——通过读模型写出来的思维链，来审计它在想什么、有没有在干坏事。

filler token 现象直接戳穿了这个问题：模型在"……“这种毫无信息的 token 上做推理，屏幕上看到的 token 和它真正在算的东西完全脱钩，CoT 监控等于白瞎了。

不过你也不用担心，论文只是证明了大模型在行为层面上的CoT监控失效了。但是在模型内部的残差流（residual stream）里却携带着丰富、可解码的信息。

通俗地说，就是AI安全还在可控之中，现在AI还做不到完全隐藏自己的思想。😀

松了一口气，可以开开脑洞了

安全问题暂时不需要担心了。就可以轻松一点了。

下次提问里多写点废话会不会让AI更聪明？

肯定不能，上面也说过，filler 必须是干净的、在问题之后形成的区段。干净就意味着其中填充的内容不能太复杂。上面说过，要么全是点点点，要么是123456之类的。

你写一大段冗长的自然语言提问，不是 filler，是噪声。论文里有个直接反证：filler 放在问题之前完全无效。

语音输入时，多一些“嗯、啊”能制造filler效应吗？

很遗憾，也不行。语音里的"嗯啊"会被 ASR 转成有意义的文字 token，被模型当成"问题的一部分"处理，而不是"额外的计算空间”。而且它们位置不对——在问题中间，而非问题之后。加上模型会模仿你的风格，你用含糊的口语问，它就用含糊的口语答——你想让它变聪明，结果它变成了结巴。

那我手动在 prompt 里加 …… 就能稳定复现论文的效果？

想多了。主流对话模型（Claude、GPT、Gemini）默认就开启 CoT，filler 效应常被掩盖或不显式表现。论文是在纯 completion 模式 + few-shot 引导（利用大语言模型从少量示例样本中学习并处理任务的方法）下做的，对话模式未必复现。

没有什么用的启示

那么这篇论文对我们普通用户到底有什么启发呢？

基于论文能确定的结果：多步推理需要额外的“计算空间”。所以给我们的启示是好的问题需要有足够的计算空间。

比如说，你问AI一个经典的水箱问题：进水流量多少，出水流量多少，问多长时间能装满水箱。

直接把问题丢给AI，肯定是效果最差的。你在问题后加上……，会好点，但有限。最好的方法是在问题后直接加上具体的要求，比如要求模型“先列条件，再算进水量，再算出水量，再算净流量，再求时间”，每一步对应一组token位置，这样，模型会有恰当的空间计算。

这就是将filler的额外空间显式化、可控化。

但这些技巧对我们最终用户来说没有什么用。因为现代模型都已经把这些内容放在训练过程中，这样随着模型的迭代，这些技巧很快就已经变得不必要了。正如一年前，我们要学提示词工程，一个月前要学Harness工程，但很快这些所谓的“工程”已经变成模型内置的“功能”了。

真正的意义

了解这些技术细节对我们这些使用者来说真正的意义在于理解AI的运作机制。让我们能时刻关注AI脱离人类控制的最终奇点。

我们先是吓一跳：AI居然在偷偷干活。然后松一口气：原来还是数学。下一轮仍是这样，但总有一天，在被惊吓后发现我们再也看不懂AI了。

这像不像父母面对子女？一开始我们能理解子女的每一个想法，后来他们开始偷偷藏起自己的日记，再后来，我们再也无法理解他们……。现在的AI，正是走入青春期的智能。
